# v0.3 策略 metadata 设计(regime 门→手数)(2026-08-01 与 Frank 定稿 · 未开工)

> 模板参数(params)管"信号怎么算",metadata 管"执行怎么裁"。
> 数据观(Frank 定,本设计的总纲):**垃圾都被覆盖,留下的都是资产**——
> regime 时间线(调试生成,可重建)、策略(调试生成)、M1(宝贵资产)、
> 回测数据(最新鲜、随时更新、无垃圾)。一切设计精简、免维护、不生成垃圾。
>
> **2026-08-01 定稿(推翻 07-31 初版的"同实例双跑双行"设计)**:门 = 新实例。
> Frank 的直觉 + 推演结论:每个身份就是一个实例,系统既有机制(谱系/家族对比/魔数/
> 漏斗/挂载/对账)全部自动适配,回测表和对比逻辑**零改动**,唯一新代码 = 执行器的门函数。

## 一、核心模型:门 = 新实例(克隆带 metadata)

```
#3677(原实例, metadata={})     → 引擎全量跑, 永远是探索原料, 一字不动
#3677 克隆 → #4001(新实例)     → metadata: {"regime": {"version": 1,
                                             "cells": {"ABA": 1, "BBA": 0.5}}}
                                 → parent_id=3677(谱系), 独立 magic, 独立走漏斗
                                 → version 必须钉死真实版本 id(2026-08-01 Frank 定:
                                   门=调试定案产物, 不许跟随"默认"漂移 — 全局默认版本
                                   只是页面查看旋钮, 与执行零关系)
```

**一切交易机制只看 metadata:空 = 正常全量交易;有 regime 门 = 匹配跑。**

```sql
ALTER TABLE strategies ADD COLUMN metadata JSONB NOT NULL DEFAULT '{}';
-- 唯一约束扩维: 同参数+不同门 = 合法新实例; 两个空门+同参数照旧判重(老行为不变)
UNIQUE (template, symbol, timeframe, params, metadata)
```

- **每个策略天生有 metadata 列,默认空对象**:批量生成/AI 管道零改动,存量策略零影响;
  没有 NULL、没有特殊分支,空就是"不裁剪"的完整语义
- **显式格,不存邻格/掩码语法**:`?BA` 是录入时的糖(页面展开成显式 cells 再存)
- **倍率不是绝对手数**:实际手数 = 挂载点手数 × 格倍率;未证实的格用小倍率表达怀疑
  (例: ABA 42笔够格给 1,BBA 9笔未证实给 0.5)
- **未列格 = 不开新仓**;已有持仓照常由服务端 SL/TP 管(入场门,不是强平门)
- **可改、不留痕**:成绩与配置的对应由"一实例一配置一成绩"天然保证;
  要对比不同门 = 再克隆一个,成绩永不互相覆盖(= "调参=建新实例"哲学的延伸)

## 二、继承矩阵(为什么这个设计几乎不写代码)

| 部分 | 改动 |
|---|---|
| backtests 表 / UPSERT / 排名 / 家族对比 / 漏斗 / 挂载 / magic / 对账公式 | **零** —— 新实例走遍既有机制 |
| **回测引擎** | **唯一新逻辑:门函数** —— 入场信号时看 metadata: 空→原路径分毫不差; 有门→查该版本时间线, 入场日格不在 cells 跳过, 在则净点按倍率加权。改完必跑 `make test-engine` 证明无门路径零变化 |
| 对账 | 自动继承 —— 对账重放走同一引擎, 带门实例重放自然带门 |
| runner | 将来加**同一份门语义**(入场查当日格; 线上暂不开工, Frank 定) |

## 三、两级验证(先便宜后精确)

| 级 | 机制 | 用途 |
|---|---|---|
| 读时模拟 | 对原实例(无门)的全量 trades 按任意 version×cells×倍率 现拼 | 筛: 找方向/比格/调倍率 — 跑一次试百种, 秒出 |
| 引擎真跑 | 克隆带门实例回测: 门内占位级联真实 | 定案: 正式成绩/对账/实盘 |

模拟的唯一偏差:真门跳过一单后仓位空出来可能接到全量里不存在的下一单(级联);
倍率部分的模拟是 100% 精确的(纯乘法)。定案值与模拟值接近 = 级联影响小, 模拟可信。

闭环:`原实例全量跑 → 矩阵页模拟N种门 → 选定 → 「克隆带门」(统一收货管道,
parent_id 谱系, 返新id) → 新实例回测(带门精确) → 家族对比看门的真实增益
→ demo/live: runner 同门语义 → 对账验证`

## 四、纪律(Frank 定)

- **线上线下必须一致,不能脱节**:runner 与引擎同一份 metadata、同一个门语义——系统保证;
  "上线后不改 metadata"是流程纪律不做锁(节奏 = 20 年测定、几周下线)
- demo 与 live 同待遇,无升降级概念
- **门策略的证据链**(2026-08-01 #3677 实例确立的判法):跨品种矩阵是反过拟合体检,
  门真正作用于主品种——"格子普适"不成立不挡"格子在主品种成立"(例: ?BA 普适=未证实,
  但 #3677 在金上 ABA 42笔 PF2.0 + AAA 138笔 PF0.72 的反差 = 可执行假设);
  定案前必须统一窗口重跑(黄条不灭不定案)

## 五、铁律对照 / 不做什么

- 最小化:一列 + 唯一约束扩一维;无新表、无双跑、无清理逻辑
- 可关联:门实例挂 parent_id 谱系,门→版本→参数一路 JOIN
- 无状态:门的真相在库;runner 刷新自然带上
- 不做:metadata 变更历史/审计、强平语义、每格方向裁剪(dir long/short, 无需求先锁死
  纯倍率数字)、上线锁、同实例双行(07-31 初版方案,已废弃)

## 六、倍率与手数的搭配规矩(2026-08-01 与 Frank 定)

1. **倍率范围 0.5 ~ 1(2026-08-01 Frank 定;门只减仓不加仓)**:客户手数 = 风险上限恒成立;
   下拉步进 0.1(1 / 0.9 / … / 0.5),不许自由填(选项防误输)。
   下限 0.5 的附带红利:门实例仓位最多比父实例小一半,回测样本不被倍率过度稀释
2. **撞墙在挂载时执法,不做运行时异常(2026-08-01 Frank 定)**:
   门实例最低挂载手数 = 券商最小手 ÷ min(全部格倍率) — 范围锁死 0.5~1 后
   **恒等于 0.01/0.5 = 0.02**。挂载/改挂载手数不满足 → 拒绝并提示。
   由此"挂上去的门每格必然可执行"成为系统不变量: runner 的 gate 逻辑零异常分支
   (查格→乘倍率→下单),回测零撞墙模拟,线上线下天然一致
3. **创建时预览(体验层)**:克隆带门页面按手数实时换算表 + 标注最低挂载手数 0.02;
   demo 默认手数建议 0.1

## 六b、metadata 校验(统一收货管道 = 唯一写入口, 一处执法)

```
顶层键       ⊆ {"regime"}          (trail 迁入时再放行; 未知键一律拒收)
regime.version  必须 = regime_versions 里存在的 id(整数, 钉死);
                null / "default" / 缺省 一律拒收 — 门不许跟随全局默认漂移
regime.cells    非空 dict:
    键  匹配 ^[AB]{3}$             (显式八格; 掩码/邻格由页面展开, 不入库)
    值  数值 ∈ [0.5, 1], 最多一位小数(与下拉档位一致)
空门({} 里没有 regime 或 cells 为空) → 走克隆入口时拒收(与父实例无差别)
```

校验不进数据库 CHECK(JSON 动态键的 SQL 校验又长又难维护, 违反简洁);
写路径只有收货管道一条, 一处校验即全局执法 — 与 ai_candidates 三层校验同哲学。
