## 口径

**锚点 A = 跑批当天**（每次运行现取当天日期，冻结进本次报告；不可配）。同一批全部策略共用一把刀 →
批内可比（对比三铁律）。段定义按"距 A 多少年前"写，0 = 当天。
**切点时间学（钉死，测试锁定）**：年 = 365.25 天（与 v0.5 同约定）；锚点转时间戳 = A 当天
00:00 UTC；切点 = 锚点 − 年数×365.25天。笔归段按 `entry_time`，区间 = 左闭右开 `[起, 止)`。

| 期 | 训练段 | 测试段 |
|---|---|---|
| 长期 long | A−20y → A−5y（15y） | A−5y → A（5y） |
| 中期 medium | A−5y → A−1.5y（3.5y） | A−1.5y → A（1.5y） |
| 短期 short | A−2y → A−0.5y（1.5y） | A−0.5y → A（0.5y） |

段与段**有意重叠**（长测含中期全部，中测含短测）：三期分别回答"长期能不能活 / 最近几年还灵不灵 /
当下市场认不认"。

**执行路径**：每策略×品种**只跑一次 20 年回测**（jobs 队列 `kind="oos_v2"`，多 worker 并行，
与批量回测同一份 `jobs._run_one` → 引擎零改动、尺子同一把），结果 UPSERT 进 `backtests`；
六段全部是对同一份 `trades` 按 `entry_time` 过滤 + 现成 `backtest._metrics()`。
好处：机时省 3 倍，且短期段的指标是完整预热过的，没有窗口冷启动偏差。
**副作用（既有机制，声明不是 bug）**：UPSERT 覆盖 `backtests` 同键行 → 策略列表页/排名看到的
成绩变为 20 年窗口口径，与旧批（如 5 年窗）行不可混比 —— 与 v0.5"涉及淘汰必须用刚出炉的真数据、
结果回流库"同一规矩，`from_time/to_time` 在行内可追溯；本模块的筛选结论一律以报告为准。

**判定**（2026-08-06 Frank 定版）：段**合格** = PF > 该期生效门槛，或无亏损段（PF=∞，绿显 ∞），
或 **0 笔段（无数据不追责 → 算过，灰显 `—`）**；段**不合格** = 有笔且 PF ≤ 门槛（含全亏 PF=0）→ 红。
六段全合格 = **PASS**，任一红 = **FAIL**。没有第三种结论。
（引擎 `_metrics`：无亏损段 `profit_factor=None` 且笔数>0，与 0 笔段是两种返回，判定代码必须区分。）
**警示与判定分离**：0 笔段、笔数 < `min_seg_trades` 都挂 `！注意: 样本不足` —— 只提示人工留意，
不参与判定（不做不可靠的补救逻辑）。数据不足 20 年的品种 → 前面段 0 笔 → 灰 `—` 照样判，
人工从警示一眼看出。净点 / 笔数 / 最大回撤只显示不判定。

**默认不动策略状态**：预览为默认 —— 只出报告 + 给被判定过的(pass/fail)追加 `basis` 标签
`oos_v2#<报告号>`（只写 basis 一列，不改 status；skip 不打, 下次重跑）→ 下次自动出池 + 报告溯源。
执行模式额外把 FAIL 归档（死因 `oos_v2_fail` 可逆，写入重申 CANDIDATE）；点名诊断恒零写入。

## 配置（唯一源 = `config.oos_v2`，探索期编辑区在本页，稳定后搬配置页）

```json
{
  "segments": [
    {"name": "long",   "label": "长期", "train": [20, 5],  "test": [5, 0],   "min_pf": null},
    {"name": "medium", "label": "中期", "train": [5, 1.5], "test": [1.5, 0], "min_pf": null},
    {"name": "short",  "label": "短期", "train": [2, 0.5], "test": [0.5, 0], "min_pf": null}
  ],
  "default_pf": 1.0,
  "min_seg_trades": 10,
  "batch_limit": 50
}
```

- **PF 门槛两层**：每期 `min_pf`，`null` = 用 `default_pf`。现在全 1.0；将来填
  `long 0.8 / medium 1.0 / short 1.2` 就地生效，不改代码。报告显示实际生效值。
- **回测窗口不单独配**：= 各段最早起点自动取最大（现在 20 年）。少一个能和段定义打架的源。
- 页面可编辑：每期的 训练起/止、测试起/止、该期 PF（空=默认）+ 默认PF/提示笔数/单次上限。
  **第一版不做加期/删期按钮** —— 加第四期直接改库里数组（仍是配置不是代码），省掉一堆边界校验。
- 每次运行把整份判据**快照**写进报告 → 老报告永远按当时口径自解释，改判据不篡改历史。

## 表（schema/061）

```sql
CREATE TABLE IF NOT EXISTS oos_v2_screens (
    id         SERIAL PRIMARY KEY,       -- 报告号: basis 标签 oos_v2#<id> 溯源到本行
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    mode       VARCHAR(8)  NOT NULL CHECK (mode IN ('preview','execute')),
    anchor     DATE        NOT NULL,     -- 锚点 A = 跑批当天
    scope      JSONB       NOT NULL,     -- {task, ids|label}
    params     JSONB       NOT NULL,     -- 段定义 + default_pf + min_seg_trades 快照
    summary    JSONB       NOT NULL,     -- {total, passed, failed, skipped, not_run, warned}
                                         --   warned = 带「样本不足」警示的策略数(0笔段或<min_seg_trades)
                                         --   skipped = 任务失败/缺回测行(铁则1, 永不归档)
    details    JSONB       NOT NULL,     -- 逐策略六段 {pf, net, trades, dd} + verdict + reason
    owner_id   INTEGER
);
```
`backtests` / `strategies` **不加列不改约束**。

## 数据安全铁则（照 v0.5，改代码前先读）

1. 任务 FAILED / 缺回测行 → 该策略记 `skip`，**永不归档**；
2. 执行动作（若开）必重申 `status='CANDIDATE'`；
3. 预览模式除【报告 + 出池标签(basis)】外零写入；点名诊断恒零写入；
4. 判定是纯读+纯计算，引擎路径不在本模块；
5. 收尾完删空本工种队列 = "队列空即无待收尾批次"，幂等自清理（不加表不加列）。

## 效率预期

第二轮起靠 `oos_v2#` 标签出池，只跑新策略。
