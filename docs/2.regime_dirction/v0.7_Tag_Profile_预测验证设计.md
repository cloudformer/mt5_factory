# v0.7 Tag / Profile / 预测验证（+ regime_abstract 实验台）设计

2026-08-08 与 Frank 定稿。目标：策略从"一个回测结果"升级成"有生命周期、验证履历、
市场适应画像的完整对象"。四件套，按批次实施，每批可验证。

## 总原则

- **一切决策都是读数**：Profile 读时现拼不落库（原料全在库里，不造第二份要同步的副本）；
  **唯一必须落库的新数据 = 预测快照**（Expected 必须在 create time 冻结 — 防泄露的本质）；
- 所有阈值/词表配置化，不硬编码；
- regime 只描述不预测的铁律不变 — 预测验证模块是对"门"价值的**事后验尺**，不是让 regime 去预测；
- 最终产出愿景：**秘方文档** = feature 定义版本 + 状态键 + 策略参数 + 该状态 20 年统计 +
  预测验证战绩，每项可 JOIN 溯源，导出即成文。

## ① Tag 系统（批次 1）

`strategies.tags` 新列（JSONB 数组，默认 `[]`，schema/064）。筛选履历专用：
**只追加、永不修改已有元素**；`basis` 回归本职（生因/批次文本）。

元素三字段（2026-08-08 Frank 定名）：
```json
{"report": "oos_v2#6", "status": "pass", "created_time": "2026-08-08T09:10:10+00:00"}
```
- `report` = 真实报告名（词根#报告号，JOIN 回报告表取六段全量数据）；
- `status` = pass / fail；`created_time` = 收尾时刻（UTC，存全时刻保排序，显示可只给日期）；
- skip 不追加（留池下次重跑 — 缺数据不定论）；预览/执行都追加（出池机制）；
- **v1 暂不写入**（老 basis 标签机制不动）；未来任何筛选器用同结构写自己的真实报告名；
- 状态类聚合 tag（OOS_ALL_PASS / DEMO_RUNNING…）是**推导值**不落库：从 tags 履历 + status
  现算，词表/推导规则配置化 — 不造第二份要同步的状态。
- 兼容：存量写在 basis 里的 `oos_v2#2~#5` 不追改；oos_v2 出池过滤同时认 tags 与老 basis。
- 页面：策略列表标签列 = tags 彩色（绿 pass / 红 fail，悬停看时间）+ basis 文本；
  「标签/生因」搜索 = basis 与 tags 一起模糊（`oos_v2#`、`pass` 都能捞）。

## ② Profile（批次 2）

`GET /strategies/{id}/profile` 现拼 dict，零新表。骨架（在 AI 成绩单基础上扩 regime 维度）：
```
{ base:      {id, name, template, symbol, timeframe, params, status, created, owner, origin},
  history:   tags 履历 + basis + archive_reason,
  stability: {窗口内 20Y/5Y/2Y 的 PF·净点·DD·笔数(从 backtests.trades 切, 与 oos_v2 同刀法)},
  oos:       最近一次 oos_v2 报告的六段结论(报告号可跳转),
  states:    {状态键: {pf, trades, win_rate}}(逐笔贴当日格现算, 口径版本参数化),
  live:      demo/live 战绩(strategy_stats) + 对账可信度(reconciliations),
  prediction: 该策略的预测快照列表 + 当前验证读数(批次 3) }
```

## ③ 预测验证（批次 3）

**冻结日 = 策略 metadata（regime 门）的生成日期**（天然存在不可篡改）。

新表 `predictions`（唯一落库）：
```
id / strategy_id(FK) / state_version / state_key / created_at(冻结时刻)
expected JSONB  -- {pf, win_rate, dd, trades_per_year, window_days} 冻结时按之前数据算死
```
Actual 侧**读时现拼**：冻结日之后的成交（回测重放 + 实盘）按同一状态过滤现算。

**评分口径**（2026-08-08 定，全配置化，不做合成分）：
- 成熟度门槛：验证段 `笔数 ≥ 20 且 天数 ≥ 90`（配置）才出结论，之前 = "未证实(已验证X天/Y笔)"
  — 单笔/近期不能验证（Frank 2026-08-08 强调）；
- 读数1 **保持率** = Actual PF / Expected PF（1.5→1.2 = 0.80）；
- 读数2 **同期增益** = 门内 Actual PF / 同期无门全量 PF（regime 预测价值的真尺子：
  市场整体变差时门救命 = 增益>1，门无信息 = 增益≈1）；
- 结论三档：有效(Actual>1 且保持率≥0.8) / 衰减(Actual>1 但<0.8) / 失效(Actual≤1)。

## ④ regime_abstract 实验台（批次 4，另行定稿后做）

口径实验页：配任意 feature 定义参数 → 现算实验 timeline（不落库）→ 记分卡
（口径评定四标准：持续性/覆盖均衡/区分度[全中性,禁用策略盈利选口径]/维度不冗余）
→ 可选策略池切片预览 → 满意才冻结成 regime_versions 新版本。AI 配参数走 AI 调参同款模式。
两层结构: 指标函数库(代码注册, 有限词汇: ma_side/ma_slope/atr_regime/range_pos…) ×
口径定义(配置自由组合 features + 参数), 状态键 = 各 feature 桶字母拼串; 现有 v1/v2 = 三 feature 特例。
**维数护栏(2026-08-08 Frank 定): 3~4 维最佳(8~16 格)** — 页面默认 4 维上限(可配),
超出只警告不硬拦, 反正记分卡的覆盖均衡(最稀格≥5%)/持续性(格龄中位≥3天)会把爆炸口径判死:
20年≈5200交易日, 5维32格平均160天/格, 8维256格≈20天/格=纯噪声必过拟合。
