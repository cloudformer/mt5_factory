# v0.11 筛选·策略×regime 映射规律(2026-08-11 与 Frank 定稿)

页面: 策略 ▾ → 筛选·策略×regime 映射规律 (`/regime-map`)
代码: `services/regime_map.py` + `routes/regime_map.py` + `views/regime_map.py` + `regime_map.html`
+ `schema/070_regime_map.sql`(仅报告表) + `jobs.py` 的 `regime_map` 分支

## 它只问一件事

**这个策略的盈亏,能不能被某个 regime 口径的八个格分出层次?**

不问"哪个 regime 版本更好",不问"该不该挂门"。就问一句:同一批交易,按天气贴格之后,
出场方式的比例在八个格之间有没有真差别。

## 铁律: 各版本【独立】评估,绝不跨版本比较

Frank 2026-08-11 原话:「第一个 regime 按性别分,第二个 regime 按上衣颜色分,
**分对了是拟合,分错了是浪费时间**」。

v1 的 BBA 和 v4 的 BBA 不是同一个东西 —— 第三位「高波」在 v1 用 q0.5 定义(一半日子算高波),
v4 用 q0.75(只有前 25%),同名不同义,交易集也不重合。所以:

- 「四个版本都说 BBA 最差」**不是**稳健性证据,是四个互不相干的不显著观察,不可叠加;
- 跨版本挑最好的那个 = 在 4版×8格 = 32 个格子里翻石头,必然翻出漂亮的;
- 本页因此**不排名、不选最优、不做任何跨版本比较**,每个版本自己出结论。
- 多重比较家族 = 主判据 × 版本数 → Bonferroni α = 0.05/N(不是 0.05/3N)。

## 四类 = 出场原因(2026-08-11 换掉 R 倍数分类)

| 类 | 含义 |
|---|---|
| 止盈/锁利 | `reason` = tp / tsl |
| 正常止损 | `reason` = sl |
| 跳空有利 | `reason` 含 gap 且净点 > 0 —— 缺口/滑点帮了忙 |
| 跳空不利 | `reason` 含 gap 且净点 ≤ 0 —— **止损被打穿,这是执行风险不只是盈亏** |

未知/手动 `reason` 按盈亏兜底进正常两类,所以四类恒等于 100%(单测 ① 守着)。

### 为什么废掉原来的 R 倍数四类(大赢/小赢/小亏/大亏)

第一份真实报告(#72 `ma_cross-GBPUSD-M15-fast14-rr2.4-sl_points250`, 2917 笔)当场证伪:

```
大赢 27.7% · 小赢 1.9% · 小亏 0.0% · 大亏 70.4%
```

固定 SL/TP 的策略上 R 倍数分类**必然退化**:

- `rr=2.4` → 所有止盈都是 2.4R,全落进「大赢」,「小赢」只剩 1.9% 的零头;
- 佣金 7 点让正常止损变成 −257 点 > 1R(250)→ 全部落进「大亏」,「小亏」清零;
- 结果四类塌成两类,而「大亏」丢掉了它唯一的语义(本该是"被跳空打穿"),分类白做。

出场方式不受 rr 和佣金影响,而且 gap 两类直接回答一个真问题:
**哪种天气容易被跳空打穿**。

## 两道笔数门(2026-08-11 补,修一个假信号 bug)

富集倍数 = 该类中此格占比 ÷ 此格整体交易占比。判信号必须**同时**满足三条:

1. 富集 ≥ 1.5x
2. **该格总笔数** ≥ 30(格本身不是碎格)
3. **该类在该格笔数** ≥ 10 ← 新加的门

原来只有第 2 条 → #72 报出的三个"有信号"全是假的:

```
v1 小赢在ABA富集2.32x(7/163笔) · v2 1.95x(11/305) · v4 3.77x(3/43)
```

底下只有 3~11 笔。富集是个相对数,分母越小越容易炸;第 2 条只管分母(该格总笔数),
管不住分子。单测 ⑤/⑥ 一正一反把这道门钉住。

## 直读优先: 格内占比比 p 值更能说明问题

页面表格每格显示两行 —— 上=笔数,下=**格内占比**(这种天气下这么出场的比例);
富集倍数挪到悬停。理由:富集是"相对本类全局"的相对数,看着刺激但小格子会炸;
格内占比可以直接横向比,也可以直接和最右列的全局占比比。

**八个格的百分比都贴着全局值 = 这个 regime 口径对本策略没用**,这是不用看 p 值的直读证据。
#72 的 v1 就是教科书例子(全局大赢 27.7%):

| 格 | 总笔数 | 大赢占比 |
|---|---|---|
| ABA | 163 | 23.9% |
| AAA | 269 | 26.0% |
| BBA | 556 | 26.4% |
| AAB | 667 | 28.8% |
| BBB | 314 | 29.3% |
| BAB | 210 | 33.8% |

23.9%~33.8% 全挤在 27.7% 附近 —— 八个格的盈亏结构几乎完全一致。
Frank 肉眼直接看出来了(「即使这个数据我没看出什么信号」),数字完全支持。

## 显著性 = 置换检验,不查卡方表

保持每笔的**类别**不变,只把格标签在交易之间随机重排 1000 次 → 零分布 → p。
切断"类别↔格"的对应,同时保留四类占比和各格交易量结构。
不查卡方表的原因:格大小极不均(667 笔 vs 43 笔)时卡方近似不准。

结论三档:有信号(p<阈值 且过三道门)/ 弱(p 显著但富集全靠碎格)/ 无信号(p≥阈值)。

## 工程

- 纯计算,**不跑引擎**:复用 `backtests.trades` + `regime_timeline`,只读库;
- 走 jobs 队列(`kind=regime_map`),`CHUNK=10` 个策略一块 —— 块数就是并行度,
  之前 CHUNK=50 时 200 个策略只切 4 块,9 个 worker 只有 2 个在干活;
- 置换检验是 CPU 密集的,必须 `asyncio.to_thread` —— api 进程自己也消费任务,
  同步跑会卡死事件循环(现象: CPU 99%、进度条卡在 0/4、连 progress 都查不动);
- 插件式可移除 = 删本页四件套 + `app.py` 两行 + `DROP TABLE regime_map_screens`。
