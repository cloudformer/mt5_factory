## 对账算分口径:被原谅缺口(2026-07-30 与 Frank 定,不过度严苛)

> 算分唯一源 = `_finalize_recon(matched, dir_ok, outcome_ok, n_a, n_b, one_sided, forgiven)`。
> `forgiven` = 有良性归因的缺口笔数,记为 **full match**(信号/方向/涨跌三率全算);
> **只有真差异才扣分**。并集用真配对(被原谅的仍是真实信号,不虚高)。
> 改对账口径/算分前后必跑 `make test-engine`。

| 缺口类型 | 现在算 | 三率(笔数/方向/涨跌) |
|---|---|---|
| 真配对 | ✅ 匹配 | 全算 |
| 拒单(止损太紧被 10016 拒) | ✅ 记为匹配 | 信号+方向+涨跌全算 |
| 持仓占位(级联,live/bt_holding) | ✅ 记为匹配 | 全算 |
| 数据缺(重放跑不了) | ✅ 记为匹配 | 全算 |
| 回测真无信号(not_triggered) | ❌ 真差异 | 扣分 |
| 实盘该下没下·无归因(疑似漏单) | ❌ 真差异 | 扣分 |

**为什么这样定**:被拒是被动的(券商执行差异,不同券商规则不一)、持仓占位是单仓互斥的
级联下游症状、数据缺是重放跑不了 —— 这些都不是"系统漏单",信号+执行都到位,算 match;
只有"实盘该下没下且无归因(疑似 runner 漏单)"和"回测真无信号"才是真差异。
过度严苛(把良性缺口都算漏)会让综合分虚低、失去信心。原因全部对账**自己推算**
(SL vs stops_level / 持仓区间 / 数据覆盖),**不依赖 worker 日志**(日志会归档、非结构化)。

## 一、数据设计定版(2026-07-19 与 Frank 确认,不再讨论)

现状是对的,记录在案防止将来被"改进":

| 设计 | 内容 | 为什么对 |
|---|---|---|
| 回测结果 UPSERT 覆盖 | `UNIQUE(strategy_id, symbol)`,重跑就地更新,不留历史流水 | 免维护;今天和两周后重跑笔数本来就不同,留旧版无意义 |
| 调参 = 建新实例 | 改参数不改旧策略,新参数=新 strategies 行(parent_id 谱系) | 每个实例的回测终身对应同一套参数,对比走家族表 |
| 对账 = 事后回归防线 | 实盘 vs 回测逐笔配对,匹配度掉=引擎/数据出问题报警 | 真实路径的持续验证,多数系统没有 |

对账防线的边界(所以才需要下面的代码测试补位):**事后**(要有实盘成交才验得到)、
只覆盖实盘走过的路径 —— OOS 切分、跳空成交、跨品种验证、SL/TP 同 bar 顺序这些分支验不到。

## 二、代码回归测试计划(未来做,改引擎前必须)

**原理**:把"已知输入 → 应得输出"写死成用例,机器一键复核。改完代码跑一遍,
输出变了立刻报警 = 改坏了;不跑实盘、不碰数据库、秒级完成。

**覆盖清单**(按风险排):

1. **撮合引擎** `services/backtest.py`
   - 合成 K 线(手造 10~20 根 M1)→ 断言逐笔:入场价(开盘+点差+滑点)、出场价、净点、reason
   - 悲观规则专项:SL/TP 同 bar 先碰 SL;跳空按实际开盘成交(reason=sl_gap);佣金扣减
   - 边界:数据缺分钟、首/末 bar 开仓、一根 bar 内进出
2. **OOS 切分**:固定成交序列 → 断言 7:3 切点时间戳、train/holdout 各自笔数与净点、两段相加=全量
3. **对账配对** `_reconcile_metrics`(纯函数,最好测):构造实盘/回测两组时间戳 →
   断言配对数、方向/涨跌匹配率、漏单/未触发归因、±容差边界(差 1 秒配上/配不上)
4. **净点换算**:价格移动 ÷ point 各品种口径(0.01 / 0.00001);point 变更场景(联动 point 哨兵(待排期))

**形式**:pytest,用例进 `containers/api/tests/`;合成数据全部代码内构造,不依赖库/网络;
CI 里 push 即跑(deploy.yml 前置一步)。先写 1(撮合)就值回票价,2/3/4 增量补。

**验收**:改任何引擎代码,`pytest` 全绿才可合;新增悲观规则必须先补用例再改实现。
