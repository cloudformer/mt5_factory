## 三档归类(排期用)

- **真·零风险,可放心先铺**:v5.0-A、v5.1、v5.2、v5.3(纯加法,没人读新东西);
- **低风险但有工作量**:v5.4、v5.5(不碰现有逻辑,但是新页面/端点,费工不费险);

## 现状快照(2026-07-25)

### ✅ 已完成(全部线上验证)

1. **阶段1 地基**(schema 033~036):users 表 / 策略 owner+visibility / api_keys /
   user_config 覆盖层 / mt5_hosts.owner / quota_* 配额键;
2. **5.0 挂载全链**:挂载表+回填 → runner 按机器认领(双向兼容零停机)→ 状态联动
   自动挂载(池内最少负载一台,不全挂)→ 挂载列全 AJAX 管理 → stats/对账按账户;
3. **5.4 市场**:可见性列+筛选+打标端点(公开/共享二次确认)+ 只读市场页 +
   红线含 name(shared 连名字都不显示 — 名字嵌参数);
4. **5.5 管理后台**:独立"管理"导航组 — 建用户/启停 · API keys(curl 用法备注)·
   worker 钥匙(签发/吊销/绑定列)· worker 归属只读 · 配置覆盖(写/删=回默认);
5. **worker 钥匙体系**(schema/040):发钥匙即扩容、每机一把(明文一次/sha256)、
   announce 认钥知主+一机一钥首绑+吊销即解绑、**归属只读跟钥匙走**(手动划拨三层已删);
   两台机器已持证绑定;
6. **5.6 识别层最小版**:api 中间件解析 X-API-Key(用户/worker 钥匙)→ 是谁挂到
   request.state + last_used + 日志,**零拦截**;runner 请求已带钥;
7. **身份重排**(直接写库):owner = id 1(名 admin, 纯管理零资产);frank = 交易用户
   (6341 策略 + 2 worker + 2 钥匙,新资产默认归他);
8. **定案入档**:角色两分法(owner/user, 租户内 admin/viewer 记前瞻)·
   配额只记录不拦截 · 盲测不落库 · 通信单向化选型 REST(v7.2)。
