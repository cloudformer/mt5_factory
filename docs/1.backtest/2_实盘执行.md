# 实盘执行原理(runner:demo 模拟 + live 真金)

> 术语:"实盘"是纯 UI 汇总概念(= demo + live,真实下单,与回测相对);
> **数据库没有"实盘"字段**,库里只有 `env` = DEMO / LIVE。
> 全 Python 方案:策略代码只有一份(`strategy_core`),回测和实盘跑同一个策略类,只换适配器。

## 一、挂载与认领(策略怎么到 worker 上)

```
策略页点"挂载" → strategy_mounts 表加一行(策略id, 主机id, 手数)
     ↓ ≤15 秒
runner 刷新: GET /strategies/status?host=本机名
     ↓ api 按两把钥匙过滤: ①挂载表 host_id=我 ②status 匹配我的角色(demo机领DEMO/live机领LIVE)
worker 就地重建本地策略对象(make_strategy), 不重启
```

- 挂载是**多对多**:一策略可挂多台(多账户同时跑,每挂载点独立手数),一台可挂多策略
- 改参数/手数/状态 = 改数据库,worker 下一轮自动跟上,永远不改代码不重启

## 二、运行节奏(两个循环,算信号零查库)

| 循环 | 间隔 | 干什么 | 碰库 |
|---|---|---|---|
| 主循环 | 10s | 处理收盘 bar:本地策略对象算信号 → 下单;写心跳 | ❌ 全本地 |
| 刷新 | 15s | 拉"我该跑哪些策略"清单(轻量,JOIN 挂载表只发我的) | ✅ 查库失败保留旧清单继续跑 |

每根**收盘 K 线**:取已收盘 bar(只用收盘,不看未收盘)→ `on_bar` 出信号 →
从 **MT5 读当前持仓**(按 magic 认领,不信任内存)→ 有信号且空仓 → 下单;持仓占位 → 跳过。

## 三、执行纪律(铁律,换取 Python 方案可靠性)

1. **只做 bar 级策略(M1+)**,不做 tick 级高频(方案硬边界)
2. **每笔订单必带服务端 SL/TP**——runner 挂了持仓仍有券商侧保护
3. **runner 无状态**:启动时从 MT5 读持仓/挂单、从 DB 读配置重建,不信任内存
4. 同机部署 + 看门狗自动重启 + 心跳上报;每策略独立 magic、异常隔离
5. **不同 worker 不得共用同一 MT5 账户**(同账户双跑 = 重复下单),数据库唯一索引执法;
   demo 与 live 不能同机
6. **magic = 100000 + 策略id**(全系统不变量:api 分配 / runner 下单 / web 归因三处依赖;
   999999=下单测试,0=手动)

## 四、下单与回写

- `order_send`:现价 → 按券商精度取整 → 校验最小手/停损距离(stops_level)→ 带 SL/TP 发单;
  filling mode 按 symbol 能力位判断(IOC/FOK 字面位掩码)
- 止损太紧(< stops_level)会被券商 10016 拒单——对账侧把这类拒单**记为匹配**(见对账文档)
- **成交回写 `trades` 表**(回合粒度,与 MT5 100% 镜像:方向/出入场价/盈亏/佣金/swap/净点/env),
  与回测结果同键体系可 JOIN——这是关2对账的原料

## 五、决策与事件速查(2026-08-01 定: 报错必须能"看见即知道怎么修")

runner 每策略每收盘 bar 记一行决策(act);异常类升级为事件进库(workers 页可见,
状态变化才报不刷屏,"怎么修"列给方向)。

| act / 事件 | 性质 | 含义 | 修复方向 |
|---|---|---|---|
| hold | 正常 | 无信号,持有/观望 | 无需处理 |
| skip_pos | 正常 | 有信号但持仓占着(单仓互斥) | 无需处理;对账"占位级联"的最里层证据 |
| skip_gate | 正常 | 当日格不在该策略 metadata.cells 里,门在裁剪(日志带 cell=今天的格 / want=门要的格) | 无需处理;这就是门在干活 |
| **skip_gate_stale** | **警报** | 当日 regime 未生成(时间线落后于今天) | 数据侧:①下载页查自动同步/下载 worker 是否把今天 M1 入库 ②Regime 页对该版本重建;期间保守不开仓,恢复自动报 GATE_OK |
| quote_lost / QUOTE_LOST | 警报 | MT5 拿不到该品种 K 线 | **Windows/MT5 侧**(与 Linux 无关):终端是否登录、品种是否在市场报价、品种名与券商是否一致;恢复自动报 QUOTE_OK |
| LOAD_FAIL bad_timeframe | 警报 | 策略周期不受支持 | 改策略 timeframe 或淘汰实例 |
| LOAD_FAIL not_in_market_watch | 警报 | 品种在该券商不可用/名字不符 | MT5 市场报价加品种,或核对拼写 |
| refused:no_sltp | 警报 | 信号没带 SL/TP(铁律拒单) | 查策略模板信号生成 |
| refused:vol_min | 警报 | 手数低于券商最小手 | 调大挂载/策略手数(带门注意最低挂载手数=最小手÷最小倍率) |
| refused:stops_level / order_fail:10016 | 警报 | SL/TP 距券商最小停损太近 | 加大 sl_points 或淘汰(参数不适合此券商);对账已把此类拒单记为匹配 |
| order_fail:10030 | 警报 | 填充模式不支持 | 升级 worker(update.ps1),新版按品种能力位自动选 IOC/FOK |
| order_fail:10019 | 警报 | 资金不足 | 减手数/换账户 |
| order_fail:10018 | 正常 | 休市时段 | 开市自动恢复 |
| OFFLINE | 警报 | worker 90 秒无心跳 | Windows 侧看 bridge/runner 进程与网络 |
