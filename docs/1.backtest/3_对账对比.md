# 对账与对比原理(关2:回测 vs 实盘逐笔对账)

> 定位:**尺子的实证防线**。对账不只是看盈亏——demo/live 实际成交与回测预期逐笔比对,
> 偏离达标才说明"回测模型对该策略是准的"。匹配度掉 = 引擎/数据出了问题,报警。
> 本质(2026-07-25 定):我们是做尺子的,尺子必须管用(可信回测)+ 对比必须一致。

## 一、对比三铁律(凌驾一切,违反即数字无效)

回测 vs 实盘、版本 A vs 版本 B,**除待测变量外全部锁死**:
1. **统一时间**(无运行区间则用实盘单边时间)
2. **统一配置**(含插件开关)
3. **统一手数**

## 二、配对机制

- **运行区间**(`strategy_runtime`):只比策略真实在跑的时段;无区间降级单边(分母=实盘侧)
- **双边分段配对**:实盘笔 vs 回测重放笔,入场时间 ±N 分钟窗口内配对(默认 2,可配);
  窗口内抓漏单,两边都有归因
- 时间口径:两边都是券商服务器时间,直接比,不转换

## 三、算分公式(唯一源 `_finalize_recon`,2026-07-30 定)

```
union  = n_actual + n_backtest - matched          (并集, 用真配对)
paired = matched + forgiven                       (被原谅缺口记为 full match)
笔数率 cr = paired / union
方向率 dr = (dir_ok + forgiven) / union
涨跌率 or = (outcome_ok + forgiven) / union
综合分 = 100 × (0.4×实盘覆盖 + 0.2×cr + 0.2×dr + 0.2×or)
达标(q10): cr ≥ 90% 且 dr ≥ 90%
```

## 四、被原谅口径(不过度严苛:只有真差异才扣分)

| 缺口类型 | 算法 | 三率(笔数/方向/涨跌) |
|---|---|---|
| 真配对 | ✅ 匹配 | 全算 |
| 拒单(止损太紧被 10016 拒) | ✅ 记为匹配 | 信号+方向+涨跌全算 |
| 持仓占位(级联,live/bt_holding) | ✅ 记为匹配 | 全算 |
| 数据缺(重放跑不了) | ✅ 记为匹配 | 全算 |
| 回测真无信号(not_triggered) | ❌ 真差异 | 扣分 |
| 实盘该下没下·无归因(疑似漏单) | ❌ 真差异 | 扣分 |

**为什么**:被拒是被动的(券商执行差异)、持仓占位是单仓互斥的级联下游症状、数据缺是重放
跑不了——信号+执行都到位,不是"系统漏单"。归因全部对账**自己推算**
(SL 距离 vs symbols.stops_level / 持仓区间 / 数据覆盖),**不依赖 worker 日志**(会归档、非结构化)。

## 五、精度与哨兵

- **精度偏差**:入场均差 / 净点均差 / 总账偏差(逐笔复现率是尺子可信度的实证)
- **point 漂移哨兵**:对账时抽 3 笔现算现比,漂移亮红条 + 一键按原始价格批量刷新缓存净点
- **成本实测校准**(规划):≥50 笔后用偏差中位数复核滑点 3/佣金 7 的假设

## 六、小样本纪律

留出段/实盘笔数少 → 结论只是"**未证实**",不是"已证明"——两个方向都不定案
(短 OOS 窗口好坏都可能是随机幸运儿)。数据会攒够,尺子在,答案早晚自己浮出来。
例:177×trailing k=4.5 样本内四指标全赢、留出段 -92% —— 半小时用数据否决一个
看起来完美的想法,这就是尺子的价值。
