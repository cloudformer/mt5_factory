# 回测原理与逻辑(库内模拟)

> 术语:回测 = 库内模拟。数据只来自数据库(Windows worker 下载落库的 M1),
> 引擎不碰 MT5。定位 = 漏斗关1:**故意悲观**,让"回测亏 = 必亏,直接删"这个方向的结论可信。
> 改撮合/OOS/对账代码前后必跑 `make test-engine`(v2.4 回归网,37 用例)。

## 一、数据地基

| 设计 | 内容 | 为什么 |
|---|---|---|
| 只下载 M1 | 唯一原始数据;M5/M15/H1/D1 全部按时间桶聚合派生 | 消灭多源打架;缺分钟属正常(按时间戳分桶不按根数) |
| 数据来源 | 从实际交易的券商服务器下载 | 信号层零出入两纪律之一 |
| 时间口径 | K线时间 = 券商服务器时间,永不转换;库存 UTC(timestamptz) | bar 边界、对账窗口依赖 |
| M1 红利 | 高周期 bar 内走势可用 M1 拆解 | 解决 SL/TP 同 bar 顺序盲区 |

## 二、悲观撮合规则(宁可低估,逐条写死)

1. **只在收盘 bar 决策**,信号在下一根 M1 的**开盘价**成交(不偷看未来)
2. 买按 ask(开盘 + 点差 + 滑点),卖按 bid;**点差用每根 bar 记录的真实值**
3. SL/TP 按 M1 逐根检查;**同一根 bar 同时碰到 SL 和 TP → 先碰 SL**(悲观)
4. **跳空**越过 SL → 按实际开盘价成交(亏损比 SL 更大,reason=sl_gap),不假装在 SL 价出场
5. 佣金、滑点、swap 全算(默认滑点 3 点/佣金 7 点,config `backtest_costs` 可改,批次内冻结口径一致)

方向性结论:悲观口径下**回测亏 = 实盘必亏**(可直接淘汰);回测赚 ≠ 实盘必赚(还要过关2对账)。

## 三、反过拟合(批量生成必有靠运气的漂亮曲线)

- **OOS 切分**:训练 7 : 留出 3,留出段亏损一票否决
- **最少交易笔数**:小样本假象过滤
- **跨品种验证**(空间维度):同参数在全部 download 品种各回测一行,看普适还是单品种巧合;
  批量模式有交叉门槛(主品种够格才交叉),按 ID 点名不设限
- 参数邻域稳健性(±10~20% 邻居也得赚)——规划中
- 所有阈值做成配置,不写死

## 四、执行与存储

- **任务队列**:批量回测拆成"策略×品种"jobs(数据库即队列,`FOR UPDATE SKIP LOCKED` 抢单,
  租约回收,重启续跑);消费者 = api 内 1 路 + worker 容器 N 副本(`make up WORKERS=N`),
  失败整单回队从头重跑,不接力、无中间状态
- **结果存储**:`backtests(strategy_id, symbol)` 主键 UPSERT 就地覆盖,含指标包 + 逐笔 trades;
  不留历史流水(重跑笔数本来就不同,旧版无意义)
- **调参 = 建新实例**:改参数不改旧策略(parent_id 谱系),每实例的回测终身对应同一套参数
- **窗口**:默认 config `backtest_window_days`(180 天),可选 5/10/15/20 年;
  跨品种对比必须统一窗口(对比三铁律)

## 五、指标口径

- 净点 = 价格移动 ÷ symbols.point(每品种自己的单位,**跨品种不可直接相加比较**)
- PF = 总盈点 ÷ 总亏点(无亏损 = ∞);胜率、最大回撤、分年明细
- point 漂移哨兵:对账抽笔现算现比,漂了亮红条 + 一键按原始价格刷新缓存值
